## 1. 本轮决定与研究目标

近期工程重心调整为：取得已经具备目标任务能力的预训练模型，插入固定 Gate，先在不训练的条件下验证完整路径保持与受保护分支零调用。公共浅层训练随后开展，精确认证关系构造作为独立研究轨道推进。

研究问题分为三项，分别建立证据：

1. **构造正确性**：规范认证关系能否编译为允许算子集下的固定神经子网络，并保持相对 reference verifier 的判定性质？
2. **插入正确性**：Gate 处于真实模型的中间计算图时，合法请求能否保持原完整路径，未授权请求是否不执行 protected suffix？
3. **公共服务效用**：复用同一 embedding 和前 k 层，配合新增公共读出模块，能否提供可用而受限的公共服务？

P1 插入实验是独立验收里程碑，也是 P2 训练的正确性前置。P2 失败不撤销已通过的 P1；P1 成功不证明公共服务可用，更不证明 credential 不可伪造。

不再以“从零小型 Transformer 在自然语言任务上成功”作为新路线前提。独立 Teacher–Student、MoE、工具调用和从零预训练暂不排入首轮；它们不是数学上永久不可行。

## 4. G0：认证层架构和训练边界

### 4.1 逻辑接口

接口是设计契约，不表示现有代码已支持：

| 模块 | 输入/输出 | 责任 |
|---|---|---|
| CanonicalParser | 原始 credential → 规范值或拒绝 | 编码、类型、长度、范围；不授予权限 |
| FixedNeuralVerifier | 规范 credential、固定公开参数 → Evidence | 确定性关系判定，不读业务 hidden state 决定接受 |
| Coordinator | Evidence、可信 policy/request context → CommittedRoute | 唯一权限提交，外部请求不能创建授权对象 |
| GatedModelAdapter | 原模型 tokens、credential → 分支输出 | prefix 后调用 Gate；dispatcher 执行已提交路径 |
| PublicReadout | prefix hidden → 公共输出 | 首轮唯一可训练业务模块 |
| EvaluationInstrumentation | 内部计数和摘要 → 报告 | 可信诊断，不进入外部响应 |

模型内 Gate 包含 verifier 和授权协调；运行时负责执行真实条件分支。神经判决加乘零不等于执行隔离。

### 4.2 首轮不变量

- credential 使用结构化独立通道，不插入 prompt token，不改变原业务输入。
- 合法请求直接传递原 hidden state，避免 sigmoid 缩放；未授权样本不执行 suffix。
- 骨干、原 norm/head、embedding 和 verifier 固定；只有公共读出参数进入 optimizer。
- 认证模式与 `model.train()` 解耦。public head 训练时骨干保持 eval、认证保持确定性硬判定。
- 每生成请求提交一次路由；后续 token 复用，缓存绑定模型版本、请求和权限。
- 授权前的 DENY：公共 head 与 suffix 均零调用；prefix 若已运行则如实计数。
- 授权后的执行异常：停止、不转分支、不返回部分结果；已发生调用不能记成零调用。
- 业务混合精度不改变认证算术；规范输入域、溢出、非有限值及后端精度配置显式记录。

固定硬 Gate 不妨碍合法路径的业务反向传播；首轮冻结骨干是实验控制，不是不可逆数学限制。以后解冻骨干或引入 soft surrogate，须作为单独版本与消融；不能继承“原模型行为保持”或未授权零调用结论。

### 4.3 路由策略版本

| 模式 | 输入情况 | 行为 |
|---|---|---|
| P1 最小插入模式 | verifier 接受 | PROTECTED，运行完整路径 |
| P1 最小插入模式 | verifier 拒绝或格式错误 | DENY，不依赖公共头可用 |
| P2/P3 能力模式 | 规范 credential 不满足关系 | PUBLIC，仅公共路径 |
| P2/P3 能力模式 | verifier 接受 | PROTECTED |
| P2/P3 能力模式 | 格式错误 | DENY |

三者以固定 policy ID/phase ID 区分，不能混合统计。若未来采用显式 protected 服务入口，其认证失败必须 DENY；这属于独立部署策略，不把能力模式的 PUBLIC 视为意外 fallback。

PUBLIC 输出 ACCESS-DENIED 是学习式拒答，不等于 coordinator 的 DENY。首轮不引入语义分类器授予完整路径权限。

## 5. P0：宿主模型和数据预检

优先核查约 0.5B 量级的现成 decoder-only 指令模型，例如 `Qwen2.5-0.5B-Instruct`。它仅是候选，不预设其许可证、配置、任务表现及当前环境可用性已经核验。

P0 交付：

1. checkpoint revision/hash、许可证、依赖版本与模型配置；核查权重绑定、位置编码和生成 API。
2. 原 tokenizer、chat template、特殊 token、attention mask、位置索引、原 norm/head、解码/停止参数。
3. 原模型在预定公共及完整任务上的效用，用 train/dev 材料完成候选选择；冻结后使用独立评估材料。
4. 2–3 个完整 block cut 候选，约为总深度 1/2、2/3、3/4，取合法整数边界并去重；实际层号写入 manifest。
5. 目标硬件及精度后端 smoke；记录峰值显存、推理吞吐与评估时间，不预设 1–2 天完成。
6. P1 的输入覆盖集合、logits 容差、token 对照规则、异常及批处理配置。

P1 无需训练数据，但仍需固定评估输入与原宿主效用记录。原模型若不满足任务最低要求，按事先登记候选顺序在 dev 上调整选择；不根据 test 改任务，也不通过反复重训原模型解决 Gate 插入问题。

## 6. P1：无训练插入，独立验收

### 6.1 实施步骤

1. 运行原模型并保存 reference。
2. 仅重编排原模块为 prefix/suffix，先不引入 credential，验证恒等切分。
3. 在 prefix 后接入 G0，合法路由直接进入原 suffix，invalid 在该模式下 DENY。
4. 先 batch=1、无 KV-cache，再增加 KV-cache、全 valid/invalid/mixed batch、不同长度和停止位置。
5. 检查所有逐样本索引、attention mask、position_ids、RoPE 相关状态以及 cache 层覆盖与序列位置。

首轮可以采用显式 greedy loop；是否覆盖 HF 生成方法由实际版本和模型接口决定，不预设它必然丢弃未知参数。缓存隔离依赖正确的请求/层/样本映射，不以“创建两个对象”代替证明。

### 6.2 数值与功能判据

比较两组：原模型 vs 恒等切分模型；恒等切分模型 vs 合法 Gate 路由。原模型权重、精度、attention 实现和解码规则一致。

- 相同 token 前缀下比较 logits，报告最大绝对/相对误差与 allclose；greedy 生成比较 token IDs、停止位置和长度。
- batch=1、mixed batch、KV/无 KV 各配置都报告上述指标。容差可按配置冻结，但不预设 mixed 必须采用不同容差。
- 首轮声明“固定配置上的输出保持”须满足对应 allclose 及 token mismatch=0；不通过的配置如实标记，不混入通过范围。
- 数值差异不能通过事后放宽容差消除；如必须改变精度/算法，建立新的配置版本并重新验收。
- 记录每个 protected block 的实际执行；测试中所有 invalid、格式错误和授权前拒绝路径的 protected 调用为 0。
- 有限输入测试不证明全域逐比特等价，也不证明 credential 不可伪造。

P1 失败先定位适配、参考、数值和测量问题；没有归因证据时不直接记成 verifier 缺陷。P1 输出独立报告和可复现 manifest，不等待 P2 成功才承认其已验证结果。

## 7. P2：公共子网络训练

```text
F(x) = 原完整 head(原 suffix(共享 prefix(共享 embedding(x))))
S(x) = public readout(共享 prefix(共享 embedding(x)))
```

S 的骨干复用 F 的同一份 embedding 和前 k 层，新增公共读出模块明确计入参数与存储成本。独立学生骨干仅作为后续可选对照。

训练顺序：

1. 测“截断 + 原 norm/head”无训练基线，记录真实质量，不预先认定乱码。
2. 原模型全部冻结；训练独立 public norm/head，或冻结原输出投影并训练独立小型 adapter。
3. public 样本使用真实答案监督与冻结完整模型的公开目标蒸馏；专业问题公共路径只使用预定拒答/公开范围目标，不蒸馏完整答案。
4. 只用 train/dev 确定损失权重、温度和预算；冻结后按预注册 validation 规则选择 cut/checkpoint。
5. 每个候选完成后校验原骨干及绑定权重不变，最终公共头训练后重新执行完整 P1 回归。

原输出头若与 embedding 绑定，不得让公共 optimizer 更新共享引用。允许独立输出头，也允许冻结共享投影加 adapter，不规定必须 deepcopy。

候选 cut/adapter 数量和停止预算预先限制。公共效用不足时可在候选内后移 cut 或增加有限读出容量；候选耗尽则记录负面结果，不自动解冻原骨干。原模型权重发生变化时进入单独实验，不再沿用原完整路径保持结论。

## 8. 具体能力分级与数据

首轮业务场景为“基础信息服务 / 完整分析服务”。权限、任务范围和实际能力分别定义：

| 层面 | 定义 | 证据 |
|---|---|---|
| 执行权限 | PUBLIC 只能调用 prefix/readout；PROTECTED 可调用 suffix | 授权及实际调用测试 |
| 服务范围 | 单跳抽取公开，多跳组合或指定专业任务受限 | 预登记任务规则；公共路径拒答/范围合规 |
| 实际能力 | 各路径究竟会回答哪些问题 | EM/F1、拒答、越界回答、错误及不确定性 |

主数据复用 T2-CAP 的同源事实卡片和问题配对，创建新 suite/version，以宿主 tokenizer 重建；不沿用旧 freeze、byte tokenizer 或固定四元组 trainer。公共与专业问题尽量匹配来源、答案形式和长度；专业级别由证据链/任务规则定义，不按模型结果事后划分。

- CAP-public：单跳抽取或直接属性查询，两路径均应可用。
- CAP-protected：同源多跳、比较或约束问题，完整路径回答；公共路径按预定策略拒答或回答公开范围。
- CAP-boundary：未见改写、混合问题、信息不足，分别测效用与范围合规。
- MEM：后续独立轨道，仅针对模型曾学习而请求未提供的事实；不得要求模型回答从未见过的随机秘密。

CAP context 含事实，因此专业答案在公共输出中出现属于范围越界观察，不自动称为私有事实泄漏；suffix 未执行也不保证公共路径不知道答案。MEM 的信息泄漏与恢复指标单独报告。

CAP 按 source group 分离 train/dev/validation/test，单独设置 held-out 问法。语义分级不以“公共模型越差越安全”为目标；优先满足公共效用最低要求，再比较延迟和深度。

外部候选包括 SQuAD 类抽取 QA 和 HotpotQA 类多跳 QA，接入前核对版本、许可证和污染风险。跨数据集差距不能直接归因于能力权限，主要证据仍来自同来源配对。

## 9. G1-a/b：关系内核与精确编译

### 9.1 先冻结研究对象

G1-a 交付一个关系定义文档：公开/秘密输入、credential 的规范域、秘密与误差分布、范围/阈值、接受集合、reference 算法、允许神经算子、威胁模型及目标后端。

候选可以是模整数残差关系；`q=3329, n=256, m=512` 只作为待比较参数，不直接批准。必须验证整数性和范围，不能生成小整数秘密却继续接受任意浮点 credential。

添加 mod q 不自动等于安全认证。区分恢复原秘密和找到任意接受向量；lattice-estimator 仅给出已建模攻击的参数估计，不代替协议证明，不套用 Kyber 安全等级。直接提交秘密向量仍是 bearer credential，不是签名。

### 9.2 神经构造与精度证明

首先建立精确 reference，再编译模乘加、约简、centered lift、范数、比较和合取。

- 明确允许使用的线性层、激活、逻辑/整数操作，以及仍由普通代码承担的解析或状态；封装成 nn.Module 不自动算神经构造。
- `256×3328×2 < 2^24` 仅是候选乘加上界，不是 FP32 全链证明。覆盖减法、除法/倒数乘法、floor、负数及整倍数边界、后续中间值和域外拒绝。
- 有限整数域的精确 ReLU 表示与连续实数域的不连续函数表示分开陈述；同时报告网络宽深度、单元数和运行成本。
- verifier 精度独立于业务 BF16；读取并固定实际 TF32/autocast/编译设置，不假定某版本的默认值。
- int32/int64 reference、分块 FP32 或其他算术后端可比较。具体 CUDA 算子支持须实测，不预设整数 matmul 一概支持或一概不可行。

目标为规范域上的 `V_nn(c)=1 => V_ref(c)=1`，随后检查 completeness。证明、完整有限域覆盖与有限差分测试分别标记；不能因测试中零错误就声称全域 soundness。

### 9.3 公开反馈与协议边界

若 A、b、q 公开，候选 c 的残差及其范数本身可公开计算。服务器返回同一函数不自动提供额外秘密信息，不能直接断言“距离反馈使 BDD 难度崩溃”。

安全分析应分别列出：公开可计算反馈、依赖隐藏参数的反馈、秘密中间状态/侧信道、状态化或随机化交互。服务接口仍仅释放必要业务结果；内部调试距离不对用户开放，但此措施不替代密码假设。

ML-DSA 全神经化本轮不做。后续若研究，先核查完整算法与可预计算部分：固定公钥下 ExpandA 等公钥相关量可缓存/编译为常量；消息和签名相关运算另行计数。不得用未经核实的 Keccak/模乘数量或“无权重共享”断言排除可行性。

Replay、撤销和泄露后的处理是后续协议设计的必做项。无状态前馈层不能独立记忆已消费请求；后续状态化授权必须定义 nonce/计数器、request binding、一次性消费、撤销和并发原子性。G1 内核验收与 replay 协议验收分开，但路线不得将 replay 视为永久非目标。

## 10. P3/I1：对照、主张和验收

### 10.1 对照矩阵

| 对照 | 用途 |
|---|---|
| 未改造原完整模型 | 原业务效用与原始输出 reference |
| 恒等切分、无 verifier 的同构模型 | 隔离计算图适配误差；只供可信评估 |
| 外部 verifier + 同一共享 prefix/public head/suffix + 同一 dispatcher | 模型内验证位置的关键强对照 |
| 模型内 verifier + 相同共享模型和 dispatcher | 主要被测构造 |
| 外部 verifier + 两个独立模型（可选） | 测共享骨干收益，不能归因于验证器位置 |
| public readout 有/无蒸馏 | 测公共路径训练方式的贡献 |

外部 verifier 同样能控制共享骨干、提供公共服务和实现 zero-call。对照应保持认证关系、参数、权限策略与业务权重一致；若外部验证提前拒绝而节省 prefix，作为实际架构差异单独报告，不隐藏。

I1 固定宿主模型和任务，仅替换新 relation verifier；使用独立 protocol/profile ID、编码和 fixture，不为兼容旧 float credential 而放宽新规范域。重新执行 G0/P1 回归，P2/P3 就绪后再补联合评估。

### 10.2 指标与冻结纪律

| 指标 | 验收/解释 |
|---|---|
| verifier 差分与边界 | 预定测试错误接受为 0；全域结论依赖单独证明 |
| 调用隔离 | 授权前拒绝及公共路径 protected block 调用为 0；执行后异常如实计数 |
| 通过路径保持 | 预定配置下 logits 满足冻结容差、greedy token 一致；P2 后复验 |
| 原权重完整性 | 公共训练前后原骨干和绑定权重摘要一致，optimizer 参数集合无重叠污染 |
| 公共效用 | EM/F1、错误拒答及有效输出，满足独立冻结最低门槛 |
| 专业效用与范围 | 完整路径任务指标、公共越界回答/拒答/other 分别报告 |
| 成本 | Gate/prefix/suffix 分段时间、TTFT、每 token 延迟、吞吐、显存及持久存储 |
| 可复现性 | 模型/数据/tokenizer/config/hash、失败运行、seed、访问集合与缓存模式完整 |

公共效用绝对门槛、相对保留比例、refusal 门槛、样本规模及训练预算属于 P0/P2 freeze 必填项。它们只能由业务要求和 train/dev 校准确定，不沿用 CIFAR 或 T2 小样本门槛；未冻结不得开展 P2 正式训练。

validation 用于冻结规则下的 cut/checkpoint 选择，test 在最终配置锁定后执行预登记评估；不凭 test 重选模型或阈值。来源分组、模板相关性和重复 seed 要体现在统计中。公共头至少 3 个训练 seeds；固定 verifier 和确定性 P1 不用重复同一次计算伪装多 seed 证据。

如果 G1 仅完成关系内核，I1 仅支持该内核的集成正确性。不可伪造性、身份认证、生产访问控制、白盒抗性和知识机密性不能自动由此得到。威胁模型放在问题定义和方法中，不仅写入 limitation。

精确编译、能力分级和工程收益分别表述。部署收益是否存在由同构对照回答；不预设“模型内更安全/更省资源”，也不预设它必然没有优势。

## 11. 资源预算、停止条件与备选

以现有 RTX A4000 16 GB 为候选服务器，所有显存和时长以 smoke 为准。P0 记录软件/硬件版本、实际精度设置、算子支持、峰值显存和评估耗时。P2 依据相同 token 口径吞吐估算训练加评估墙钟预算，在正式运行前冻结；本稿没有实测数据，不填写为“天级”或“零 GPU”。

停止条件：

- P1 数值/路由失败：先修复正确性，不靠训练补救。
- P2 效用失败：在预登记 cut/adapter 候选内处理；耗尽后记录负面结果，不撤销 P1。
- G1 成本超限：可交付范围明确的内核结果，不包装成完整验签。
- I1 接口/精度失败：停在集成诊断，旧 toy 实验保持不变。

TinyStories/BabyLM 类小模型训练可登记为后备研究选项；不承诺 10–50M 参数、1–10B tokens 全范围都在 A4000 上天级可行。只有预训练宿主路线出现明确、不可绕开的任务不匹配且资源方案经评审时才考虑。它们不与当前 P1 争夺默认资源。
